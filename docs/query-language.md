# Query Language

pcke includes a structured query DSL for searching the knowledge base
and traversing the typed-event graph.

## Grammar

```
query        = collection clause*
clause       = where | as_of | order_by | limit
collection   = IDENT
where        = "WHERE" (traverse | conditions)
traverse     = "TRAVERSE" "(" edge_name ("," named_arg)* ")" "FROM" STRING
named_arg    = IDENT "=" (NUMBER | STRING | IDENT)
conditions   = condition (("AND" | "OR") condition)*
condition    = field operator value
as_of        = "AS" "OF" STRING
order_by     = "ORDER" "BY" field ("ASC" | "DESC")?
limit        = "LIMIT" NUMBER

field        = IDENT ("." IDENT)*
operator     = "=" | "!=" | "<" | ">" | "<=" | ">=" | "CONTAINS" | "MATCHES"
value        = STRING | NUMBER | BOOLEAN
```

## Collections

| Collection | Notes |
|---|---|
| `nodes` | Knowledge nodes (kn:) — files, functions, types from `pcke scan` |
| `relations` | Module dependency edges (rel:) |
| `notes` | Free-form notes (nt:) added via `pcke note add` |
| `evolution` | File-rename history (el:) — retired in v0.10+, regenerated by next scan |
| `constraints` | Auto-detected build/lint constraints |

The graph (`e:`/`d:`/`l:`) is queried via `TRAVERSE` against any
collection — see below.

## Standard fields

| Field | Type | Description |
|---|---|---|
| `type` | string | Entity type: `"module"`, `"function"`, `"class"`, ... |
| `name` | string | Entity name |
| `file_path` | string | Source file path |
| `module` | string | Module name |
| `tags` | string | Comma-separated tags |
| `language` | string | Programming language |

`pcke schema describe <collection>` shows the full schema for any
collection. New fields can be added at runtime via `pcke schema alter`
(see the Schema Evolution doc).

## Standard examples

### Simple equality

```
pcke query 'nodes WHERE type = "module"'
```

### Compound queries

```
pcke query 'nodes WHERE type = "function" AND module = "auth"'
pcke query 'nodes WHERE language = "go" OR language = "python"'
```

### CONTAINS / MATCHES

```
pcke query 'notes WHERE tags CONTAINS "security"'
pcke query 'nodes WHERE name MATCHES "Handle.*"'
```

### Sort + limit

```
pcke query 'nodes WHERE type = "module" ORDER BY stability DESC LIMIT 10'
```

## Graph traversal — `TRAVERSE`

`TRAVERSE(...)` inside a `WHERE` switches the executor into graph mode:
results are the typed refs reachable from a starting node, optionally
filtered by edge type, depth, and direction.

```
collection WHERE TRAVERSE(<edge_name>, depth=N, edge='type', direction=forward|reverse|both)
           FROM '<startkey>'
           [AS OF '<timestamp>']
           [ORDER BY <field> ASC|DESC]
           [LIMIT N]
```

| Argument | Default | Notes |
|---|---|---|
| `<edge_name>` (positional) | required | Conventional name (`edges`, `rel`, `links`) — accepted opaquely; the typed-event log stores edges in a single namespace. |
| `depth=N` | 0 → graph default (5) | Maximum hops. |
| `edge='type'` (alias `type='type'`) | empty (any) | Restrict to a single edge type, e.g. `'imports'`, `'decision_link'`. |
| `direction` | `forward` | One of `forward`, `reverse`, `both`. The string form `'reverse'` also works. |

### Examples

Find every node reachable from a file via 2-hop import edges:

```
pcke query "nodes WHERE TRAVERSE(edges, depth=2, edge='imports') FROM 'e:internal/kdb/db.go'"
```

What depends on this btree implementation? (reverse traversal):

```
pcke query "nodes WHERE TRAVERSE(edges, depth=3, direction=reverse) FROM 'e:internal/kdb/btree' ORDER BY ref DESC LIMIT 20"
```

Both directions, with a time-pin:

```
pcke query "nodes WHERE TRAVERSE(edges, direction=both) FROM 'e:cmd/pcke' AS OF '2026-04-01'"
```

`TRAVERSE` and regular `WHERE` conditions are **not** combinable in
v0.10.0 — use one or the other. (Combination is tracked for v0.11+.)

## Time-travel — `AS OF`

`AS OF '<timestamp>'` pins reads to a moment in the past. Accepted
formats:

- RFC3339: `'2026-04-01T12:30:00Z'`
- RFC3339 with nanoseconds: `'2026-04-01T12:30:00.123456789Z'`
- Date-only: `'2026-04-01'`

When combined with `TRAVERSE`, the traversal sees the version of every
link that was active at the supplied time; tombstoned edges (lifecycle
= superseded by that time) are skipped.

```
pcke query "nodes WHERE TRAVERSE(edges) FROM 'e:foo' AS OF '2026-04-01'"
```

In v0.10.0, `AS OF` **without** `TRAVERSE` returns
`ErrAsOfNotSupported` — record-by-record time-pinning over the legacy
collections (kn:/rel:/nt:) requires reading the typed-event log
directly, which lands in v0.11+.

## CLI shortcuts

For one-off graph and decision exploration, the dedicated subcommands
are usually more convenient than the DSL:

```bash
# Graph traversal
pcke graph neighbors e:internal/kdb/db.go --depth=2 --edge-type=imports
pcke graph impact e:internal/kdb/btree --depth=3
pcke graph neighbors e:foo --direction=both --as-of=2026-04-01

# Decisions
pcke decision list                          # all decisions
pcke decision list --source=adr --severity=must
pcke decision show adr:0008-context-graph-pivot

# Version chain (works for entities, decisions, links)
pcke history e:internal/kdb/db.go
pcke history d:adr-0008
```

## Query plan

Use `pcke explain` to see the execution plan without running the
query:

```bash
pcke explain 'nodes WHERE type = "module" AND tags CONTAINS "auth"'
```

## Export results

```bash
pcke export 'nodes WHERE type = "module"' --format=json
pcke export 'nodes WHERE type = "module"' --format=yaml
```
